# Data quality and inference admission baseline

Baseline `module/data-quality-and-ai-reliability`2026-10-21. Addresses the existing mandatory data-quality/operational-reliability target. React→Java only; read-only reader/native source-kit executor for warehouse checks, no warehouse credentials/rows sent to Python. No auto repair, deletion, or arbitrary SQL/expression input. Source kit provenance remains unchanged unless source is patched.

## Quality rules

Product route `/quality`, scoped to selected Warehouse/Dataset. Authenticated reads require dataset/warehouse grants. ADMIN/OPERATOR may manage rules and run checks, with resource grants; VIEWER/ANALYST cannot mutate/run. Java resolves physical references from the current authorized catalog, engine from registry. Never trust request schema/dialect/SQL. Configuration has `revision:string` optimistic concurrency; changing metadata cannot silently bind a rule to a different object.

GET `/datasets/{id}/quality/rules` → `{datasetId,revision,rules:Rule[]}`. Empty configuration revision `0`. PUT same URL body `{revision,rules}` →same envelope; atomic replace, max20 rules, unique identifier `ruleId` (ASCII letters/digits/_/-,1..80). Rule `{ruleId,name,type,table:TableRef,column?:string,min?:string,max?:string,values?:string[],referenceTable?:TableRef,referenceColumn?:string,enabled:boolean}`. name1..120, strict fields per type. TableRef `{schema,name}` exact authorized physical identity; bounds serialized decimal strings, finite no exponent, max100 characters/precision38/scale18; ROW_COUNT bounds are integers0..9223372036854775807. Types:

- NOT_NULL: column; checked rows=count(*), violations=count of null values.
- UNIQUE: column; ignore null, checked rows=count nonnull, violations=nonnull count minus distinct count (extra duplicates, not every member of duplicate groups).
- RANGE: numeric column, at least one inclusive min/max, min<=max; checked rows=nonnull count; violations outside supplied inclusive bounds. Null handling separate NOT_NULL rule. Reject incompatible types before executing. Numeric family INTEGER/BIGINT/DECIMAL/FLOAT; UNIQUE accepts comparable STRING/numeric/BOOLEAN/DATE/TIME/TIMESTAMP. REFERENCE endpoints must share comparable canonical type or numeric family; engine comparison/collation applies.
- ACCEPTED_VALUES: comparable text column,1..50 distinct values each<=256 chars, exclude null; checked rows=nonnull count, violations=values not in configured set. Comparisons follow target engine collation, UI/response must say so; do not imply cross-engine case-insensitive equivalence.
- ROW_COUNT: no column, integer nonnegative min/max at least one, min<=max. observedValue=table count; checkedRows=table count; violations=0 if bounds hold else1 (one failed assertion, not bad rows).
- REFERENCE: source column and authorized referenceTable/referenceColumn of comparable physical type; checked rows=nonnull source count; violations=count source rows with no matching reference value via NOT EXISTS (nulls excluded; duplicates in reference cannot multiply). No raw values returned.

Unknown fields, nonqueryable/out-of-allowlist table/column, unsupported/binary/complex comparison types, unsafe identifiers/bounds and stale revision fail controlled4xx before execution. Config revision increments on successful PUT, snapshot rule list preserved in runs. All mutations audit safe actor/action/resource/revision only; no sample rows/credentials in audit.

## Runs and history

POST `/datasets/{id}/quality/runs` body `{}` →202 Run, persisted before dispatch, with at least one enabled valid rule; bounded workers/queue, no silent dropped job. Java revalidates physical context/resource authorization at execution. Use authorized read-only adapter/native executor with statement/deadline/row/byte bounds; SQL is built only from validated refs and typed literals, independently guarded. Aggregates run against full permitted table, never sample or silently apply a row limit to the input. Decimal/count values serialized strings; no floating point conversion. Max20 enabled checks, per-check<=15s, total run<=120s. Data can change between checks; report `consistency:"PER_CHECK"` and never claim a single cross-check snapshot.

Run includes frozen `rules` definitions for audit/detail. Run `{runId,datasetId,warehouseId,sqlDialect,revision,status:'RUNNING'|'PASSED'|'FAILED'|'ERROR',createdAt,completedAt:string|null,correlationId,consistency:'PER_CHECK',rules:Rule[],checks:CheckResult[],error:ErrorBody|null}`. `checks` is array of completed checks while RUNNING. CheckResult `{ruleId,name,type,table,column?:string,status:'PASSED'|'FAILED'|'ERROR',checkedRows:string|null,violations:string|null,observedValue:string|null,durationMs:number,error:ErrorBody|null}`. PASSED=all enabled rules pass, FAILED=at least one data violation, ERROR=execution/security/schema/deadline/interruption error; no fabricated zero for unexecuted checks. Preserve completed results on failure. Restart marks stale RUNNING runs ERROR without auto re-executing. Limit queued/inflight jobs, controlled503 on saturation; cleanup queued task state if dispatch rejected. No automatic retries or writes to warehouse.

GET `/datasets/{id}/quality/runs?page=1&pageSize=20` →standard Page (`items,page,pageSize,totalItems,totalPages`), newest first, pageSize<=100; GET `/datasets/{id}/quality/runs/{runId}` →Run with dataset ownership recheck. Historical definitions/counts remain snapshots, no rerun on GET. Revision conflict QUALITY_RULE_CONFLICT409, queue saturation QUALITY_BUSY503, restart QUALITY_INTERRUPTED in terminal error. Rules/run errors use standard safe envelope; no raw DB exception/SQL text/row payload. FE polls only active run, stops on terminal/unmount/context switch; old context response cannot replace new context. Catalog table counts are not hardcoded quality measurements.

## AI overload handling

Generation and semantic assistance share process-local bounded inference admission around outbound provider work, including any one permitted correction. `LLM_MAX_CONCURRENT_REQUESTS` default2 (1..32), `LLM_ADMISSION_TIMEOUT_MS` default250 (0..5000). Invalid configuration fails controlled provider-unavailable before inference. Capacity/wait counts bounded (at most N active and N waiting); cancellation/timeouts release slot, no implicit provider retry. Deterministic, native planning and metric compilation do not acquire an inference slot. Model profile selection remains request-scoped, provider credentials never enter logs/diagnostics. Saturation private503 PROVIDER_UNAVAILABLE with safe capacity message, existing Java mapping remains, no Candidate DTO change. This is single-process admission, not a distributed/account-wide quota.

## Acceptance

Unit/contract/security: roles/resource auth, strict rule type/fields/refs, revisions/empty rules, exact numeric handling, async queue/deadline/restart errors, count semantics/nulls, no secrets/rows. Read-only caller on PG/MySQL/SQLServer must prove known null/duplicate/range/value/reference violations and clean/empty cases using isolated data via app upload/registry; independent reader verifies counts. Browser create/save/run/history/context switch plus read-only role/viewport checks. AI concurrent/cancel/timeout/correction tests, plus real local Ollama request after admission change; online config untouched/no online inference. Do not raise completion scores from new routes/source count alone.
