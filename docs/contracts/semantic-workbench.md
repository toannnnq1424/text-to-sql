# Semantic workbench, local knowledge and transformation pipelines

Shared implementation contract for `module/semantic-memory-pipelines`. The public boundary remains React→Java, and Python never receives warehouse credentials or executes warehouse SQL. Engine enum stays POSTGRESQL/MYSQL/SQL_SERVER. All operations authorize the dataset and warehouse again on each call. Product routes: `/semantic`, `/knowledge`, `/pipelines`; existing Catalog/Query/History remain consumers of active data.

## Business semantic definitions

Existing GET/PUT `/datasets/{id}/semantic-model` remains the canonical active configuration. PUT is ADMIN only; it must validate nested references, expression identifiers and safe ASTs, unique metric/dimension names, dimensions compatible with metrics, timezone and SQL examples against the current physical allowlist. Definitions are immutable during query execution; updating a definition changes its semantic version and invalidates knowledge indexing. Physical metadata is always server-generated.

New POST `/datasets/{id}/semantic-model/validate` accepts the same semantic document and returns `{valid:true,semanticVersion,metricCount,dimensionCount,diagnostics:string[]}` without activation. ADMIN only. Validation delegates expression compilation to the source fork as well as Java checks; validation errors retain SEMANTIC_MODEL_INVALID.

New POST `/datasets/{id}/semantic-query` accepts `{metrics:string[],dimensions:string[],filters:Filter[],limit:number}`; one to10 metrics, zero to5 dimensions, max10 filters, limit1..1000. `Filter` is `{dimension,operator:'EQ'|'NE'|'GT'|'GTE'|'LT'|'LTE'|'CONTAINS'|'IS_NULL'|'IS_NOT_NULL',value?:string|number|boolean|null}`. Column/expression SQL never comes from this request. ADMIN/ANALYST may execute. Returns the existing Query resource with executionMode SEMANTIC and model `semantic-compiler`; history/result/export share the existing implementation. No LLM call is made for structured semantic queries.

Compiler uses configured expressions, physical refs and only declared safe join paths. Metric expressions must be aggregate, reference declared tables/columns and reject nested queries, mutation, file/network functions and ambiguous names. Joining a metric grain through a one-to-many/many-to-many edge is rejected instead of multiplying measures. Incompatible metrics/dimensions fail explicitly. Compiler output goes through native planning, Java AST/lineage validation and read-only execution, just like generated candidates.

Private POST `/internal/v1/business-plan` accepts `{correlationId,warehouseId,datasetId,sqlDialect,semanticContext,selection}`. It returns the existing Candidate eight-field shape. Private POST `/internal/v1/business-validate` takes the same envelope without selection and returns the public validation shape. Header correlation/service authentication/body bounds are identical to generation.

## Dataset knowledge

Routes `/datasets/{id}/knowledge` (GET status, DELETE ADMIN reset), `/knowledge/index` (POST ADMIN rebuild), `/knowledge/search` (POST authorized readers with `{question,limit}`), `/knowledge/examples` (GET curated query pairs), `/knowledge/examples` (POST ADMIN `{queryId}`), `/knowledge/examples/{entryId}` (DELETE ADMIN).

Status: `{datasetId,status:'EMPTY'|'READY'|'STALE'|'INDEXING'|'ERROR',schemaItems:number,exampleCount:number,embeddingModel:string,indexedAt:string|null,semanticVersion:string,schemaVersion:string,error:string|null}`. Search: `{strategy:'vector',question,hits:[{itemType,name,modelName,text,distance:number}],examples:[{entryId,question,sql,sqlDialect,source:string}],embeddingModel}`. Examples list: `{items:[{entryId,question,sql,sqlDialect,source}],total:number}`. `source` is `semantic-config` or `approved-query`. Status/counts come from persisted index state, never UI fixtures.

The fork's LanceDB MemoryStore/schema indexer and actual local Ollama embeddings are used. Namespaces include authorized dataset identity, metadata fingerprint, embedding model and dialect; changed schema/semantics cannot reuse old records. Example promotion requires a successful same-dataset query, current physical allowlist and SQL validation. Recalled examples are revalidated before model use. Positional row IDs from upstream are not exposed as stable IDs. Query result rows/secrets are never indexed. Index creation/deletion is serialized, bounded and persisted outside the image. Provider context selection consumes vector hits and approved examples while preserving required metadata/join paths and existing request-byte limits. No model-answer cache is introduced. Index rebuild is explicit through the authorized knowledge endpoint; a query never performs first-time or stale-index embedding work inline. When the index is EMPTY/STALE or optional retrieval fails, generation continues with the request's authorized physical/semantic context and the same selected model; it never switches to deterministic mode. Retrieval skips are logged with correlation ID only, without question, schema, rows or credentials.

Private POST `/internal/v1/knowledge/{action}` uses `{correlationId,warehouseId,datasetId,sqlDialect,semanticContext,question?,limit?,example?,entryId?}` with the same service token/correlation checks. Actions: status,index,search,examples,remember,forget,reset. Java is the sole public caller and authorizes each operation. Storage roots/model endpoints are server settings, never request fields.

## Transformation pipelines

Public `/api/v1/pipelines`: GET list; POST ADMIN create. `/pipelines/{id}` GET/PATCH ADMIN edit or disable. POST `/pipelines/preview` ADMIN validates unsaved definition and returns data/type previews; POST `/pipelines/{id}/run` ADMIN/OPERATOR accepts `{idempotencyKey}` and returns a persisted run. GET `/pipelines/runs` returns a paginated authorized run list; GET `/pipelines/runs/{id}` returns status/stage counts/errors and actual datasetId. All writer operations are server-authorized and separate from reader credentials.

Definition: `{pipelineId?,name,sourceWarehouseId,sourceDatasetId,sourceTable:{schema,name},targetWarehouseId,targetSchema,targetTable,datasetName,stages:{staging:Transform,warehouse:Transform,mart:Transform},maxRows,maxBytes,timeoutSeconds,status?:'ACTIVE'|'DISABLED'}`. `Transform`: `{columns:[{name,expression}],filter:string,groupBy:string[]}`. Names are identifiers; expressions/filter are parsed read-only scalar/aggregate ASTs over preceding-layer columns, never arbitrary statements. SQL is generated for target dialect. Source reads are bounded and parameter-free generated SELECT over the allowed table. Targets are new tables in a CREATE-capable import-writer namespace, with generated `_raw/_staging/_warehouse/_mart` names shown in preview. Existing objects are rejected; no implicit replacement/destructive overwrite.

Preview: `{valid:true,sourceColumns:[{name,dataType,nullable}],stages:[{name,columns:[{name,dataType,nullable}],rows:Record<string,unknown>[],rowCount:number,sql:string}],targetTables:[{stage,schema,name}],warnings:string[]}`. It executes only bounded source/derived SELECTs; creates no objects. Stages may project/rename/cast/clean/filter/aggregate with independent output schemas. All output values preserve canonical DECIMAL/BIGINT/time handling. Unsupported expressions or incompatible types are explicit validation errors.

Run: `{runId,pipelineId,status:'RUNNING'|'SUCCESS'|'FAILED',datasetId:string|null,startedAt,completedAt:string|null,stages:[{name,status,rowsWritten}],createdTables:[{schema,name}],error:ApiError|null,partialFailure:boolean}`. The saved definition/metadata is frozen at run start. Idempotency is principal+pipeline+key; replay with changed definition fails409. Writes are transactional where supported; MySQL DDL partial outcomes are reported with exact created objects, never auto-retried/dropped. On success register the mart as a Dataset with physical provenance and empty business semantics; users configure meaning in Semantic workbench. Run/status persist in metadata store; no fake stage progress or async placeholder.

## Local model profile

Online `.local/compose-app/provider.env` must remain byte-for-byte unchanged during local testing. A separate `.local/compose-app/ollama.env` holds local model configuration; `.local/compose-app/llm-profile` selects `online` or `ollama`. Compose maps host loopback to Docker Desktop host.docker.internal. Local embeddings use a separate server setting. Provider and integration test runners for this task refuse nonlocal endpoints. Ollama installation/model downloads are explicitly authorized by the user; training and online billing tests are not requested.

Private POST `/internal/v1/transform-plan` accepts `{correlationId,sqlDialect,columns:[{name,dataType,nullable}],transform}` and returns `{sql,names:string[]}`. The SQL references only `__nla_input`; Java validates and binds that input to its own dataset or parameterized preview. No rows/credentials are sent to this endpoint. Preview runs on at most20 source sample rows (fewer for wide parameter budgets) and explicitly warns that aggregates represent the sample.

Join cardinality validation has one shared5s budget and at most8 data scans for endpoints lacking a single-column primary key. Unproven uniqueness fails closed; add a database constraint or revise the definition instead of silently trusting a declared relationship. Query execution shares a monotonic60s downstream budget across context, AI/planning and database calls.

Pipeline failures also expose `error.details.outcomeUnknown:true` if a commit acknowledgement is lost. Such a failure retains created-table evidence and claims; it cannot be reported as a confirmed rollback or blindly retried.
