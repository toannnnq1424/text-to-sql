# Java ↔ native semantic planner

This private contract complements [Java ↔ Python AI](java-python.md). It is server-to-server only; React and user tokens cannot call it. Java authorizes the warehouse/dataset first and supplies the only physical catalog the planner may resolve. The planner receives no warehouse IDs, credentials, query values, or arbitrary catalog lookup capability.

## Request

`POST /internal/v1/semantic-plan`, JSON, `Authorization: Bearer <PYTHON_AI_TOKEN>`, `X-Correlation-ID` equal to `correlationId`. The body is limited to 1 MiB; unknown fields are rejected.

```json
{
  "correlationId": "corr-123",
  "sqlDialect": "POSTGRESQL",
  "sql": "SELECT COUNT(*) FROM public.album",
  "manifest": {
    "catalog": "nla",
    "schema": "semantic",
    "dataSource": "postgres",
    "models": [
      {
        "name": "nla_model_0",
        "tableReference": {"schema": "public", "table": "album"},
        "columns": [{"name": "album_id", "type": "INTEGER"}],
        "primaryKey": "album_id"
      }
    ],
    "relationships": []
  }
}
```

`sqlDialect` is exactly `POSTGRESQL`, `MYSQL`, or `SQL_SERVER`; `dataSource` must respectively be `postgres`, `mysql`, or `mssql`. Model aliases are generated by Java from the active dataset's authorized physical tables. Relationship endpoints must refer to those models and their discovered columns. Types come from JDBC metadata. The manifest is request-scoped and is not persisted by Python.

## Response and execution boundary

```json
{
  "sql": "WITH \"nla_model_0\" AS (...) SELECT COUNT(*) FROM \"nla_model_0\"",
  "sourceModels": ["nla_model_0"],
  "sourceTables": [{"schema": "public", "name": "album"}],
  "plannerVersion": "wren-core-py/0.4.0"
}
```

Python invokes the pinned native Wren manifest extractor, session context transform and CTE rewrite. No deterministic or pass-through fallback is allowed for planner errors. Java treats the returned SQL as untrusted: `SqlGuard` validates the rewritten SQL against the same authorized physical catalog, then Java compares the guard's resolved physical source set to `sourceTables` before the existing read-only JDBC execution. A mismatch fails closed. The planner never executes SQL.

Errors use the shared [error envelope](errors.md). `INSUFFICIENT_CONTEXT`, `SEMANTIC_MODEL_INVALID`, `SQL_DIALECT_ERROR`, and `SQL_VALIDATION_ERROR` fail the query before execution. Authentication, malformed payloads, body limits, timeouts and unavailable service fail closed; responses do not include native exceptions, source SQL, credentials or warehouse metadata beyond safe error codes.

## Compatibility and evidence

The native package is `wren-core-py==0.4.0`, with `sqlglot==29.0.1` and the upstream CTE rewrite source recorded in [platform reuse provenance](../platform-reuse.md). The native package currently supplies Linux x86_64 and macOS arm64 wheels, not Linux arm64; the production AI container therefore targets `linux/amd64`. The request uses only the three application dialects. This private contract does not expand the public engine enum.

Tests exercise request validation, auth/correlation, native rewrite and source lineage on all three dialects, joins, unknown physical tables, and Java guard acceptance. Container build and API smoke are recorded in [work log](../work-log.md); those checks do not claim live DB3 query equivalence or real LLM-provider behavior.
