# Nguồn warehouse / sample database / dataset

## Trạng thái dữ liệu hiện tại

Đã provision Chinook release `v1.4.5` với script native và checksum xác minh vào ba database Docker PostgreSQL, MySQL, SQL Server. Xem [provenance và lệnh tái tạo](../data/chinook/README.md). Chinook là sample transactional dùng smoke/integration tests, không phải warehouse star schema.

AdventureWorksDW đã được tải từ ZIP chính thức Microsoft, pin checksum, port projection12bảng/145.524dòng sang database cô lập `nla_adventureworks_dw` trên cả ba engine và kiểm chứng quản trị. [Manifest, phạm vi projection và hướng dẫn](../data/adventureworks/README.md) phân biệt rõ dữ liệu thật đã dựng với đăng ký/ngữ nghĩa/nạp file qua app. Đây không phải toàn bộ AdventureWorksDW; không tạo thêm dữ liệu tổng hợp để lấp nguồn thiếu.

Lưu đầy đủ sáu nguồn người dùng đã cung cấp. Chinook và projection AdventureWorksDW đã tải/provision/kiểm chứng trong Docker local; TPC-DS, Pagila, Northwind và Olist vẫn là danh mục đầu vào, chưa tải/seed trong đợt này. Không phải nguồn nào cũng là data warehouse star schema. Trước khi dùng thêm, pin release/commit, kiểm tra license, ghi checksum, giới hạn dung lượng và hướng dẫn tái tạo; không mặc định được redistribute dữ liệu vì mã nguồn có trên GitHub.

Phân biệt sample dataset ở đây với connector platform. Hai bộ mã nguồn mới do người dùng chỉ định ngày 2026-10-20 được khảo sát tại [platform-reuse.md](platform-reuse.md), inventory hash tại [reviewed-snapshots.json](integrations/reviewed-snapshots.json); danh mục engine/storage/file mở rộng nằm ở [future-connectors.md](future-connectors.md). ## Hướng lựa chọn cho triển khai

Chinook dùng smoke test nhanh cả ba engines. AdventureWorksDW bổ sung dữ liệu fact/dimension thật để đối chiếu grain, join, ngày, số thập phân và tập kết quả lớn; bản port được cô lập với Chinook. Script quản trị không tự tạo Dataset/semantic definitions trong app. Nguồn đã được dùng để ghi hình Nạp file CSV 606 dòng/11 cột trên ba engine, SQL Import 606 dòng/4 cột trên ba engine, JSON 606 dòng và fact CSV 60.398 dòng/17 cột trên PostgreSQL, cùng transformation MySQL→PostgreSQL. Reader độc lập so toàn bộ giá trị nguồn/canonical và các lớp đã ghi; 13 extension có preview UI, không khẳng định cả 13 đã persist. [Chi tiết bằng chứng/policy NULL](../data/adventureworks/README.md) phân biệt CSV empty strings với JSON null. Chuẩn bị file/parser round-trip không thay bằng chứng nạp qua app; kết quả chức năng/data không tự là nghiệm thu mọi state UI hoặc LLM. Trạng thái cuối theo [project status](project-status.md) và [work log](work-log.md).

TPC-DS, Pagila, Northwind và Olist vẫn là nguồn tham khảo chưa triển khai trong đợt này. Có thêm sample không thay yêu cầu tương thích ba engine của core; từng nguồn bổ sung phải được pin, đánh giá grain/type và kiểm chứng thật.

Nguồn bên ngoài không tự động thành “dataset trong app”. Quy trình rõ ràng:

1. Quản trị/data engineer lấy dữ liệu tin cậy và dựng database/schema bằng script đã review ở môi trường riêng.
2. Tạo runtime read-only user với phạm vi cần thiết; writer thuộc pipeline riêng.
3. Admin đăng ký Warehouse (engine/endpoint/credential reference), test connection, discover metadata.
4. Đăng ký Dataset với allowlist, semantic mapping, metric/dimension/rule, version.
5. Java validate semantic model với physical metadata, sau đó ACTIVE và xuất hiện trong selectors/catalog.
6. Chạy câu hỏi mẫu + expected result qua Java cho từng engine; lưu provenance và evaluation evidence.

## Hồ sơ provenance

`source URL`, release/commit, license/redistribution terms, file checksums, row counts, schema/grain, transformation per engine, data-quality checks, timezone/currency, sensitivity and retention. Chinook provenance/expected counts nằm trong [source.json](../data/chinook/source.json); AdventureWorksDW có [manifest riêng](../data/adventureworks/source.json) pin ZIP/member hashes, cột đã chọn/PK/FK và source row counts. Bulk payloads, source archive, file xuất, database credentials và acceptance reports riêng tư bị Git ignore. Bốn nguồn còn lại chưa được tải/provision trong đợt này.

## File người dùng tải lên ứng dụng

Nguồn file không cần một folder trong repo. Trong Nạp dữ liệu→Nạp file, upload CSV/TSV/TXT, XLSX, JSON/JSONL/NDJSON, Parquet, Arrow/Feather/IPC, ORC hoặc Avro. App tự đọc header và suy kiểu từ toàn bộ bản ghi, cho chọn sheet/delimiter và chỉnh mapping, preview rồi xác nhận kế hoạch vào một namespace đã cấp quyền. Java dùng prepared batches, kiểm chứng mart bằng reader, đăng ký Dataset có provenance/hash; không execute nội dung file như SQL. Chi tiết bounds/lifecycle tại [file contract](contracts/file-ingestion.md). Source registry DB→DB vẫn dành cho query/pipeline đã được quản trị; không thay flow upload bằng việc nhập thủ công từng dòng/cột.
